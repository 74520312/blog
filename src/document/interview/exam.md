### 2. == 和 equals() 的区别是什么？

**基本数据类型用==就是比较真实的数据、引用数据类型（例如String、对象、数组）用== 就是比较内存地址是否相同，**

**equals针对引用数据类型，主要用于比较里面的内容是否相同， 自定义的对象想比较就需要重写Object类中的equals和hashcode方法**



### 3. String、StringBuilder、StringBuffer 的区别是什么？

**String 在jdk1.8中是一个被final修饰的btye数组 ，拼接低效**

**StringBuilder用于字符串拼接，效率较高**

**StringBuffer同样用于字符串拼接，不过类中的方法全被synchrozied修饰，线程安全，效率较低**



### 4. Java 中的异常处理机制是怎样的？checked 异常和 unchecked 异常的区别？

**异常机制**：try 包裹代码，catch 捕获处理；不处理就向上抛，最终没人接就程序终止。

**运行时异常 (Unchecked)**：继承 RuntimeException，编译不报错，不强制处理，运行才崩。

**受检异常 (Checked)**：继承 Exception，编译标红，**必须 try-catch 或 throws**，否则编译失败。



### 5. Java 中的 final、finally、finalize 分别有什么作用？

**final**：修饰【变量、方法、类】，不能改、不能重写、不能继承

**finally**：异常处理，**最后必执行**

**finalize**：对象被垃圾回收前**最后执行一次**，现已废弃



### 6. Java 中的重载和重写有什么区别？

**重载 方法名称相同，参数个数不同，或者参数类型不同，在同一类中**

**重写 方法名称相同，参数列表保持不变，用户重写具体内容 ，继承关系中，子类重新父类的某个方法**



### 7. Java 中的抽象类和接口有什么区别？什么时候使用抽象类，什么时候使用接口？

**抽象类中方法不一定全是抽象方法，但是有抽象方法的一定是抽象类，抽象类只能单继承**

**接口中的方法都是抽象方法，变量全是常量，接口可以多实现**

### 10. JVM 的内存结构是怎样的？堆和栈的区别是什么？

**程序计数器、虚拟机栈、本地方法栈、堆、方法区。**

**堆是线程共享的，存放 new 出来的对象实例，由 GC 垃圾回收管理**



### 11. Java 的垃圾回收机制是怎样的？有哪些垃圾回收算法？

Java 的**垃圾回收（Garbage Collection，GC）** 是：

**JVM 自动回收堆内存中不再被使用的对象，释放内存，避免内存泄漏和 OOM（内存溢出）。**

**核心特点**

1. **自动执行**：不用手动 free/delete，JVM 后台线程自动处理
2. **回收区域**：**主要回收 Java 堆**（新生代 + 老年代），方法区也会回收
3. **回收目标**：**死亡对象**（没有任何引用指向的对象）
4. **核心问题**：**怎么判断对象死了？** → **怎么把死对象清理掉？**

------

**如何判断对象可以被回收？（两个核心方法）**

#### 1. 引用计数法（简单但有缺陷，Java 不用）

- 给每个对象加一个计数器
- 被引用时 +1，引用失效时 -1
- 计数器 = 0 → 判定为垃圾

**缺点**：无法解决**循环引用**问题（A 引用 B，B 引用 A，谁都不被使用但计数器不为 0）。

#### 2. 可达性分析算法（Java **官方使用**）

**这是 Java 判断垃圾的标准方法！**

- 以 **GC Roots** 为起点，向下搜索引用链
- 能到达 → 对象存活
- **不可到达 → 对象死亡，可回收**

**GC Roots 包括：**

- 虚拟机栈中引用的对象（局部变量）
- 类静态属性引用的对象
- 常量引用的对象
- 本地方法栈引用的对象

------

### 常见垃圾回收算法（面试必考 4 种）

#### 1. 标记 - 清除算法（Mark-Sweep）

**最基础算法**

1. **标记**：标记所有需要回收的对象
2. **清除**：统一清除标记对象

**优点**：简单

**缺点**：

- 效率低
- 产生**内存碎片**（大对象无法存放）

#### 2. 复制算法（Copying）

**专门用于 新生代**

1. 把内存分成**两块**（如 Eden:Survivor）
2. 只使用其中一块
3. 存活对象复制到另一块
4. 直接清空原整块内存

**优点**：速度快、无碎片

**缺点**：浪费一半空间

#### 3. 标记 - 整理算法（Mark-Compact）

**专门用于 老年代**

1. 标记存活对象
2. 把存活对象**向一端移动**
3. 直接清理端外内存

**优点**：无内存碎片

**缺点**：效率较低

#### 4. 分代收集算法（Java **实际使用**的算法）

**不是新算法，是组合策略！**

根据对象生命周期把堆分成：

- **新生代**：对象存活时间短 → 使用 **复制算法**
- **老年代**：对象存活时间长 → 使用 **标记 - 清除 / 标记 - 整理**

这就是 JVM 默认的垃圾回收策略。

------

#### 四、极简总结（背诵版）

#### Java 垃圾回收机制

- 自动回收堆内存中**无用对象**
- 使用 **可达性分析** 判断对象是否死亡
- 后台自动执行，无需手动管理

#### 垃圾回收算法

1. **标记 - 清除**：基础，有碎片
2. **复制**：新生代用，无碎片，浪费空间
3. **标记 - 整理**：老年代用，无碎片
4. **分代收集**：Java 实际使用，新生代复制 + 老年代标记整理 / 清除

------

#### 总结

1. **Java 判断垃圾用：可达性分析算法**（不是引用计数）
2. **Java 实际回收用：分代收集算法**
3. 新生代 → 复制算法；老年代 → 标记 - 清除 / 标记 - 整理
4. GC 自动回收堆内存无用对象，避免内存泄漏

### 14. ThreadLocal 是什么？有什么作用？使用时需要注意什么？

主要就是**list、set和map**吧， set是无序，不可重复  ，list是有序可重复，map是key不可重复，针对list常用的实现类有ArrayList 底层应该是一个数组 ，默认容量10，也可以通过构造设置大小，扩容因子似乎是0.75，扩大1.5倍  ，达到标准就会扩容，LinkedList应该是一个双向链表  一个节点由三部分组成，第一部分存储指向上一个节点的地址信息，中间可能是数据，最后一部分是存储下一个节点的内存地址，map实现类有hashmap底层结构有数组+链表  红黑树就，

### 17. HashMap put 元素底层执行流程（你说的就是这个逻辑）

1. 先根据 **key 计算哈希值**，算出在数组里的下标位置；
2. 如果这个数组位置**为空**，直接把键值对放进去；
3. 如果位置**不为空**，就遍历当前这条链表 / 红黑树；
4. 挨个比对 key：**hash 值相等 && equals 相等**，认为是同一个 key；
5. 找到相同 key 就**直接覆盖旧 value**；
6. 没找到相同 key，就**追加到链表末尾**。

**顺带把树化规则带上**

链表长度达到 **8**，且数组容量大于等于 **64**，链表就转成**红黑树**；

如果后续节点减少到 **6**，又退化成链表。**为什么用红黑树？** 链表查询慢 O (n)，红黑树 O (logn) 更快

```java
import java.util.concurrent.*;

/**
 * 全局业务线程池
 * 阿里规范：手动new ThreadPoolExecutor，不用Executors
 */
public class ThreadPoolConfig {

    // 1. 定义全局公共线程池
    public static final ThreadPoolExecutor BUSINESS_THREAD_POOL;

    static {
        // 核心线程数：5个常驻线程
        int corePoolSize = 5;
        // 最大线程数：最多开到10个
        int maxPoolSize = 10;
        // 空闲线程存活时间：60秒
        long keepAliveTime = 60L;
        // 时间单位：秒
        TimeUnit timeUnit = TimeUnit.SECONDS;
        // 有界任务队列：队列最多排队100个任务
        BlockingQueue<Runnable> queue = new ArrayBlockingQueue<>(100);
        // 拒绝策略：队列+线程都满了，由调用者主线程自己执行
        RejectedExecutionHandler rejectHandler = new ThreadPoolExecutor.CallerRunsPolicy();

        // 初始化线程池
        BUSINESS_THREAD_POOL = new ThreadPoolExecutor(
                corePoolSize,
                maxPoolSize,
                keepAliveTime,
                timeUnit,
                queue,
                // 简单线程工厂，给线程命名
                Executors.defaultThreadFactory(),
                rejectHandler
        );
    }
}
```

#### **线程池执行流程：**

当一个新任务提交给线程池时，线程池首先判断**核心线程数**是否已满，如果没满就直接创建核心线程执行任务；如果核心线程已经满了，就把任务放入**阻塞队列**排队，队列没满就正常入队；如果队列也满了，就判断当前线程数量是否达到**最大线程数**，没达到就新建临时线程处理任务；如果线程数也已经拉满，就执行**拒绝策略**；后续超出核心线程数量的空闲线程，等到空闲存活时间到期会自动回收，核心线程则一直常驻不销毁，等待后续任务。

### 2. 数据库的脏读、不可重复读和幻读分别是什么？

**脏读**

不是读到**错误数据**，是读到**别人没提交、随时会回滚撤销**的数据。

**不可重复读**

不是随便每次不一样，是**同一个事务内，两次查同一条数据，内容变了**。

**幻读**

不是内存没变，是**同一个事务内，两次查询，多出 / 少了别的行（条数变了）**。



前提：**两个事务 A、B 同时操作数据库**

#### 1. 脏读（Dirty Read）

**定义**：一个事务读到了**另一个事务还没提交**的数据。

- B 改了数据，没提交
- A 直接读到了 B 改的
- 结果 B 反悔**回滚**了，A 读到的就是**无效垃圾数据**

口诀：**读了未提交，随时被撤回**



#### 2. 不可重复读（Non-Repeatable Read）

**定义**：**同一个事务里，两次查同一行，数值变了**。

- 事务 A 先查一次某条数据
- 事务 B 把这条数据**修改并提交**
- 事务 A 再查同一条，发现**内容不一样了**

重点：**针对 同一条数据 的修改**

口诀：**同一事务，两次查同一行，内容变了**



#### 3. 幻读（Phantom Read）

**定义**：**同一个事务里，两次范围查询，行数变了（多出 / 少了行）**。

- 事务 A 查询 id 1~10 的数据，查出 3 条
- 事务 B **插入 / 删除**了一条 1~10 的数据并提交
- 事务 A 再查 1~10，发现**条数多了或少了**，像幻觉一样

重点：**针对 插入、删除，行数变化**

口诀：**同一事务，两次范围查，条数变了**

### 3. MySQL 四个隔离级别：

**读未提交 → 读已提交 → 可重复读 (MySQL 默认) → 串行化**

不是你说的那三个，那三个是**问题现象**，四个是**隔离级别**。

---------------------------------------------------------------------------------------------------------

**读未提交**：脏读、不可重复读、幻读 **全都有**

**读已提交**：解决 **脏读** ✅，还有 不可重复读、幻读

**可重复读（MySQL InnoDB 默认）**：解决 **脏读、不可重复读** ✅，**还有幻读**

**串行化**：三个问题 **全部解决** ✅，但性能最差

---------------------------------------------------------------------------------------------------------

**脏读**：读到别人**没提交**的数据

**不可重复读**：同事务两次查**同一行，值变了**（改数据）

**幻读**：同事务两次**范围查，行数变了**（增删数据）

### 8. sql如何优化？

#### 一、表结构设计优化

1. **字段类型合理设计**

- 能用**tinyint**不用 int，能用**varchar**不用 char；
- `varchar` 不盲目设 255，**按需指定长度**，节省存储空间；
- 固定长度字符串（手机号、身份证、编码）用 **char**，可变长度用 `varchar`；
- 时间优先用 `datetime/time`，别用字符串存时间。

1. **主键与约束设计**

- 每张表必设**主键**，优先自增整型 / 雪花 ID，少用字符串主键；
- 合理加**唯一约束、非空约束**，从源头过滤脏数据。

#### 二、索引优化（核心）

1. 常用查询字段、条件字段、排序 / 分组字段**建立索引**；
2. 遵循**联合索引最左匹配原则**；
3. **避免索引失效**：

- 不要在索引列做运算、函数操作；

- 不要隐式类型转换；

   表字段：`phone` **varchar 字符串类型**，并且给 phone 建了索引

  -- 右边是字符串 '13800001111'，和字段类型一致 select * from user where phone = '13800001111';

  -- 右边是数字 13800001111，不是字符串 select * from user where phone = 13800001111; 失效

- `like %xxx、or、is null` 容易导致索引失效；

  表：`user`，字段 `email` 建了普通单列索引

  ```mysql
  -- 查邮箱为空的
  select * from user where email is null;
  
  为什么失效？
  B + 树索引节点不保存 NULL 数据
  优化器发现要查 NULL，索引里压根没这条记录
  只能放弃索引，逐行遍历整张表判断是不是 NULL
  👉 直接索引失效，全表扫描
  
  因为 MySQL B + 树索引不存储 NULL 值，查询 is null 时索引里没有对应数据，只能全表扫描，所以索引失效；
  ```

1. 拒绝**过度建索引**：索引增删改有维护开销，只建必要索引。

#### 三、SQL 语句编写优化

1. ** 禁止 select ***

   只查业务需要的字段，减少网络传输、减少 MyBatis 实体映射开销、减少磁盘 IO。

2. 分页用 `limit` 合理分页，避免一次性查全表大量数据；

3. 多表查询优先**联表 join**，少用子查询、嵌套查询；

4. 能用 **in** 别用 `or`，大数据量慎用 in，可以改用关联查询；

5. 避免大事务、长 SQL，减少锁等待和回滚开销。

#### 四、其他优化点

1. 合理设置**分库分表、读写分离**应对大数据量、高并发；
2. 开启慢查询日志，定位慢 SQL 针对性优化；
3. 避免锁表、全表扫描，通过 explain 分析执行计划；
4. 高频查询热点数据用**Redis 缓存**，减少 DB 查询压力。



#### **总结：**

表结构合理设计字段类型、按需设长度；不 select * 只查所需字段；合理建主键和索引，遵守最左匹配、避免索引失效；优化 SQL 写法，用 explain 分析执行计划，大数据量可做读写分离、加缓存。

### 10. 哪些情况可以创建索引⭐

#### 一、必须 / 适合建索引的场景

1. **WHERE 查询条件经常用到的字段**

   经常用来做查询筛选、条件过滤的字段，必建索引。

2. **经常用于 ORDER BY 排序、GROUP BY 分组的字段**

   排序、分组不走索引会全表排序，非常耗性能，适合建索引。

3. **多表联查 JOIN 的关联字段**

   比如 A 表.id = B 表.a_id，关联字段一定要建索引，否则联表巨慢。

4. **经常作为唯一查询、精准匹配的字段**

   手机号、身份证、用户名、订单号，高频精准单条查询，适合建索引。

5. **经常用于范围查询的字段**

   `>``<``>=``<=``between` 时间范围、金额范围、日期范围，适合建索引。

6. **业务高频查询、数据量大的表**

   数据量越大，索引收益越高；小表没必要建。

------

#### 二、不适合 / 不要建索引的场景

1. **数据量很少的小表**

   全表扫描比走索引还快，没必要建。

2. **增删改非常频繁的字段**

   索引要维护，每次增删改都要更新 B + 树，**索引越多越慢**。

3. **重复值特别多、区分度低的字段**

   比如：性别、状态（0/1）、是否删除，全表大部分都是同一个值，建索引几乎没用。

4. **经常用 like % xx 左模糊、is null 查询的字段**

   建了也容易索引失效，没必要刻意建。

5. **字段值频繁变更的**

   经常 update 的字段，索引维护成本太高，不建议建。

   

#### **总结：**

经常出现在 **where 查询条件、order by 排序、group by 分组、多表 join 关联字段**，以及**高频精准查询、范围查询**的字段适合建索引；

而**小表、重复值多区分度低、增删改特别频繁**的字段不建议建索引。

### 3. Redis 的缓存穿透、缓存击穿、缓存雪崩分别是什么？如何解决？⭐

#### 缓存穿透

**请求查一个数据库根本不存在的数据**，缓存里也没有、数据库也没有，**直接绕过缓存，每次都打到数据库**。

举例：故意传不存在的用户 ID、负数 ID、恶意乱刷参数。

#### 怎么解决

1. **空值缓存**

   查不到数据库，也在 Redis 存一个空值 / 默认值，设置短期过期。

2. **布隆过滤器**⭐

   把所有合法 ID 提前放进布隆过滤器，不存在的直接拦截，不进缓存、不查库。

3. 接口参数校验

   前端 / 后台校验 ID 格式、范围，非法参数直接拒绝。



#### 缓存击穿

**热点 Key 突然过期**，瞬间大量请求同时过来，**全部打到数据库**。

特点：**一个热门 key 过期瞬间 并发打 DB**。

比如：秒杀商品、首页热门商品缓存过期。

#### 怎么解决

1. **互斥锁（分布式锁）**同一时间只放行一个请求去查库、回写缓存，其他请求等待。

2. **热点 Key 永不过期**

   逻辑上不设过期，后台定时任务主动更新缓存。

3. 过期时间加随机值避免大量 key 同一时刻集体过期。



#### 缓存雪崩

**大量缓存 key 同一时间全部失效** 或 **Redis 宕机挂了**，

大批量请求瞬间全部压到数据库，直接把 DB 压垮。

和击穿区别：

- 击穿：**单个热点 key** 过期
- 雪崩：**大批量 key** 同时过期 / Redis 整体挂了

#### 怎么解决

1. 过期时间加随机偏移，给过期时间加随机秒数，错开集体过期。
2. Redis 高可用集群，主从 + 哨兵 / Redis 集群，防止单点宕机。
3. 服务降级、熔断、限流Redis 挂了，接口直接降级返回默认值，不疯狂查库。
4. 多级缓存本地 Caffeine 缓存 + Redis 二级缓存，Redis 崩了还有本地缓存兜底。

### 5. Redis 的过期策略有哪些？内存淘汰机制是怎样的？

#### 一、Redis 过期删除策略（3 种）

Redis 给 **设置了过期时间的 key**，有三种删除策略：

##### 1. 定时删除

给每个带过期的 key **创建定时任务**，时间一到立刻删除。

- 优点：内存最及时释放
- 缺点：**占用 CPU 高**，过期 key 多会卡死 CPU，Redis 不用

##### 2. 惰性删除

**key 过期了不马上删**，等**下次再访问这个 key 时**，才检查是否过期，过期就删掉返回空。

- 优点：省 CPU，不浪费资源
- 缺点：**浪费内存**，大量过期 key 没人访问，一直占着内存

##### 3. 定期删除（Redis 默认采用）

每隔一段时间（默认**1 秒**），**随机抽取一批过期 key**，批量检查并删除。

- 折中方案：**既不耗爆 CPU，也不积压太多过期垃圾**

✅ 总结一句话：

**Redis 实际用：惰性删除 + 定期删除 配合使用**



#### 二、Redis 内存淘汰机制（满内存怎么办）

当 Redis 占用内存达到 **maxmemory 最大限制**，再往里写数据，就触发**内存淘汰**，一共 8 种策略，面试记**6 种常用**就行。

分类记忆

#### 1. 淘汰**已过期**的 key（只删带过期时间的）

1. **volatile-lru**：从**有过期时间**的 key 中，淘汰**最近最少使用**
2. **volatile-lfu**：从有过期时间 key 中，淘汰**使用频次最低**
3. **volatile-random**：有过期 key 里**随机删**

#### 2. 淘汰**所有 key**（不管有没有设过期）

1. **allkeys-lru**：所有 key 里，淘汰**最近最少使用**（**企业最常用默认**）
2. **allkeys-lfu**：所有 key 里，淘汰**使用频次最低**
3. **allkeys-random**：所有 key 里随机删

#### 3. 不淘汰（兜底）

1. **noeviction**：**不删任何 key**，直接报错返回 OOM，默认不是这个

#### **总结：**

Redis 过期策略有定时删除、惰性删除、定期删除，实际采用**惰性加定期**配合；

内存满了会触发淘汰机制，常用 LRU、LFU，分 volatile 只删过期键、allkeys 删所有键，线上一般用 allkeys-lru。
